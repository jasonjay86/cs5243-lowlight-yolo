# data

Nothing here is tracked by git except `cct20_splits/split_manifest.csv` and its
summary. Everything else is generated or downloaded and is far too large for a
repository.

## Where the data comes from

Caltech Camera Traps (CCT-20 subset), published by LILA BC:
<https://lila.science/datasets/caltech-camera-traps/>. The dataset is free for
research use; cite the Caltech Camera Traps paper if you publish anything using
it.

Download the following three items from that page and place them here:

| File | What it is |
|---|---|
| `cct20/eccv_18_all_images_sm/` | the downscaled JPEG frames, one directory of images |
| `cct20/caltech_bboxes_20200316.json` | bounding-box annotations |
| `cct20/caltech_camera_traps.json.zip` | image-level labels, the only source of truly empty frames |

The key detail: the images are downscaled to a maximum of 1024 px per side,
while the box file carries original-resolution coordinates. The harness rescales
the ground truth to match. If recall ever collapses to zero while the detector
is still firing, that rescale is the thing to check first.

## The frozen split

`cct20_splits/split_manifest.csv` is the single source of truth for every
result in this repository. It is location-disjoint: 14 train locations, 3
validation, 3 test, and no camera site appears in two splits. It was produced by
`scripts/create_cct_split.py` and is committed so that nobody has to re-derive a
split, and so that no result can accidentally be compared against a different
split.

The test locations are `28`, `33` and `88`. They are never used for model
selection or threshold tuning.

Totals: 46,231 usable images, 44,254 boxes, 3,917 empty frames, 20 locations.

## Enhanced condition sets

Each enhanced set is a directory of images plus a copy of the split manifest
whose `image_path` column points at the enhanced frames. The harness resolves
every condition through its own manifest and never guesses a directory name.

To build one:

```bash
python scripts/enhance_dataset.py \
  --manifest data/cct20_splits/split_manifest.csv \
  --method snr-aware \
  --output data/cct20_snr \
  --device cuda
```

Two things that have bitten us:

1. **Do not hand-edit an image_path column.** If a manifest is copied from
   another user's tree it will still contain their absolute paths, and every
   frame read fails with `PermissionError`. Rewrite the column to your own
   paths, or to repo-relative ones, and verify that the file count matches the
   row count.
2. **Do not delete `data/cct20_snr`.** The YOLO dataset for that condition uses
   symlinks into it, so removing the source breaks training silently.

## Rebuilding the YOLO dataset

```bash
python scripts/prepare_yolo_dataset.py \
  --manifest data/cct20_splits/split_manifest.csv \
  --annotations data/cct20/caltech_bboxes_20200316.json \
  --output data/cct20_yolo
```

This writes one class, `0 = animal`, and asserts that the box count matches the
manifest. Expect zero mismatches; a non-zero count means the annotation file and
the manifest disagree.
